# SendRack 0.7.18-fcm: confirmed shipment publishing

The vendor previously saw a successful creation dialog after a local save, before the server acknowledged the shipment. A missing/expired online session or failed upload could leave it visible only on that phone. Individual and basket confirmation now wait for authenticated server receipt. Unconfirmed records stay saved on the phone, with an inline state and Retry send. Missing/expired sessions offer Sign in to sync. Existing queued IDs/tokens are reused so retry and background sync cannot create duplicate shipments. Re-login retains unsent records. A timeout is described as unconfirmed, since the server may already have saved it.

The server replays idempotent creation-notification insertion on an existing authorized Created shipment. This repairs an interrupted notification step after the shipment transaction committed; the existing unique notification key prevents duplicate alerts. Identity, area, vehicle/capacity matching, unpaid acceptance gating, test-dispatch controls, custody, OTP and money rules are unchanged.

Validation: 84 server tests passed with no skips, including recovery of a deliberately removed creation notification through repeated creation requests with exactly one shipment/notification. Extracted APK tests used separate vendor/rider sessions: reject initial creation, show no success dialog, admin has no shipment, retry the same saved ID, admin contains exactly one record, rider receives an offer, then funding/acceptance/calls/collection complete. An offline-session UI test verifies no unauthenticated creation request and a saved queue with sign-in/retry controls. Existing History, deletion, route recovery, map-origin, quiet-dispatch and pickup browser checks passed. Final package/source asset hashes, Firebase configuration and retained signing identity verified.

Install downloads/SendRack-0.7.18-fcm.apk over ng.sendrack.test without uninstalling or clearing storage. Retained signer SHA256 d34b55d2982e55a2623157423ba2ad634ce2844c482144b53f53d88f0b8ecfa5. The compact four-vehicle banner is retained. No schema, real funding/provider configuration, secrets or hosting-resource changes.

Local/browser checks do not prove delivery of FCM to physical phones. Live Render deployment status cannot be checked from the environment because outbound Render access is blocked. Previously unsent shipments need an active vendor session and server confirmation; installing an APK alone does not prove that they uploaded.
